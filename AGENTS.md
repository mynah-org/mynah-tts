# Mynah TTS — repo contracts

## What this project is

Pure-C inference runtime for codec-based and continuous-AR TTS models. The first
target is the pinned `nvidia/magpie_tts_multilingual_357m` v2607 checkpoint plus
`nvidia/nemo-nano-codec-22khz-1.89kbps-21.5fps`; later engines are dots.tts and
Chatterbox, in that order.

The runtime is CPU-first, macOS/Linux, and has no Python dependency at runtime.
Metal and CUDA are optional build variants. The implementation plan is in
`PLAN.md`; when plan, docs, and code disagree, trust the verified code and the
converted model's `model.json`.

## Soul

- Small, cohesive C11 modules; no monolithic model file and no fake placeholder
  translation units.
- One inference state machine for offline, streaming and long-form.
- Correctness against a NeMo/PyTorch oracle before SIMD, quantization or GPU.
- Config-driven model loading; no Magpie dimensions in public headers or
  compile-time constants.
- Memory-mapped weights, reused scratch, explicit ownership, no allocations in
  the autoregressive hot loop.
- CPU is the product. GPU backends must be opt-in, resident-aware and safely
  fall back to CPU.
- Python is offline tooling only: converter, oracle, dump and evaluation via
  `uv`.

## Repository map

- `src/` — `libmynah_tts` C11 core. One cohesive component per `.c`/`.h` pair.
- `src/engine_magpie.c` — Magpie-specific composition; keep shared primitives
  in transformer/attention/codec modules.
- `cli/main.c` — `mynah-tts` command line interface.
- `server/` — optional HTTP/server layer after the core is stable.
- `tools/` — Python tooling; never required to run the binary.
- `reference/` — small extracted configs, tokenizer assets and tensor reports.
- `models/` — downloaded/converted weights, GITIGNORED and never committed.
- `tests/` — unit, stage parity, codec, streaming and e2e tests.
- `build/` — all objects and generated binaries; never build beside sources.

## Model contract

The first model pack must contain `model.json`, `tts.safetensors`,
`codec.safetensors`, tokenizer/G2P assets, `speakers.json`, `source.json` and
license metadata. The runtime must not load a raw `.nemo` file.

The current Magpie facts are only defaults until extraction confirms them:

- 12 languages and five baked-in voices;
- causal text encoder + causal audio decoder;
- frame stacking and a local transformer;
- NanoCodec output at 22050 Hz and 21.5 frames/s;
- 8 codebooks, codebook size 2016, embedding dim 32 for the selected codec.

Never assume layer count, hidden size, tokenizer, EOS IDs, local-transformer
mode, CFG defaults or tensor names. Read them from `model.json` generated by the
converter. The latest Magpie release does not provide zero-shot cloning; do not
add a cloning API by implication.

Future model families have different contracts:

- dots.tts is a 2B continuous AR model with AudioVAE, Qwen2.5-based LLM,
  flow/MeanFlow head and CAM++ speaker conditioning; it is GPU-first until a
  CPU benchmark proves otherwise.
- Chatterbox is a family, not one compatible checkpoint. Pin Turbo or
  Multilingual V3 separately; T3/Llama, voice conditioning, S3Gen/vocoder,
  alignment/EOS and watermarking are engine-specific.

Do not make Magpie's discrete codec API pretend to be a universal latent API.
Share tensor primitives and backend services; keep each engine's graph and
conditioning state explicit.

## Source of truth

- Public C API and lifecycle: `src/mynah_tts.h`.
- Pipeline/state ownership: `src/mynah_tts.c` and `src/engine_magpie.c`.
- Tensor names/shapes/dtypes: converted `model.json` and tensor report.
- Kernel behavior: scalar implementation plus per-ISA self-tests.
- CLI flags: `cli/main.c` and `mynah-tts --help`.
- Build variants and targets: `Makefile`.
- Roadmap and unresolved architecture questions: `PLAN.md`.

## Build contract

The intended commands are:

```bash
make                  # safe CPU build
make info              # compiler, OS, arch, BLAS, SIMD
make test              # unit + stage parity + available e2e
make self-test         # kernels without the large model
make bench             # RTF, TTFA, RSS and quality report
make leaks             # macOS native leak check
make ubsan             # clean UBSan build and tests
make asan              # Linux/CI; avoid as the normal macOS workflow
make metal             # explicit macOS Metal build
make cuda              # explicit Linux CUDA build
make clean
```

`make` must not require a GPU SDK. `make metal` and `make cuda` must use
separate build objects or clean rebuilds so CPU/Metal/CUDA objects cannot be
silently mixed. `make` must never download weights implicitly.

CPU BLAS policy:

- macOS: Accelerate;
- Linux: OpenBLAS when available;
- scalar kernels remain the correctness fallback;
- optimized ISA is selected with `SIMD=...`; release builds must not rely on
  `-march=native` unless the artifact is explicitly machine-local.

## Coding rules

1. Use C11, `size_t` for sizes, checked multiplication/addition and explicit
   ownership for every allocation.
2. Keep public headers free of backend-specific types. Metal/CUDA state belongs
   behind an opaque backend interface.
3. No global mutable request state. Model weights may be shared read-only;
   sampler, KV cache, codec state and callbacks belong to a context.
4. Do not allocate, parse JSON, or load files in the decode loop.
5. Keep scalar, NEON and x86 kernels numerically equivalent. Add a scalar
   reference first; do not optimize an untested formula.
6. Do not hardcode `8` codebooks, `2` stacked frames, `22050`, or any hidden
   dimension in generic code. Use model metadata.
7. Do not add a second offline/streaming implementation. Add state transitions
   to the shared path and test both sinks.
8. Do not commit model files, generated WAVs, `.o`, binaries, `.d`, benchmark
   dumps or virtual environments.
9. Keep error paths as carefully owned as the success path: failed tensor load,
   early EOS, callback abort and backend fallback must be tested.
10. Update `PLAN.md` only when a decision or milestone genuinely changes; keep
    measured results in the relevant benchmark/evaluation document.

## Text and model safety

Text normalization/G2P is model behavior, not a generic string cleanup step.
Use the tokenizer and language mapping exported by the converter. If the exact
NeMo normalizer cannot be represented in the model pack, expose an explicit
`--normalized`/`--no-tn` contract rather than silently substituting a different
normalizer.

The `.nemo` converter must validate the archive and never execute remote model
code. Save source revision, checksum and NVIDIA license metadata in the model
pack. Runtime distribution of weights is a separate licensing question from
distribution of this C runtime.

## Numerical validation

Every new stage gets a Python oracle dump before downstream work depends on it.
Use per-stage tolerances and compare:

- token IDs/argmax for deterministic generation;
- logits/hidden states with absolute and relative tolerances;
- codebook order, frame stacking and EOS position;
- waveform duration, finite values, peak/RMS and mel correlation.

Do not require byte-identical audio across different floating-point orderings or
CPU/GPU backends. For A/B tests always pass explicit identical parameters:
model revision, language, speaker, text, seed, temperature, top-k/top-p, CFG and
thread count. A model-free self-test must exist for each hot kernel.

## Performance rules

Measure before changing kernels. Report RTF, TTFA, frames/s, peak RSS, model
load time, thread count, ISA, backend and model revision. Single-request latency
and batched throughput are different metrics.

Priority order:

1. mmap and buffer reuse;
2. correct scalar matvec/attention/conv;
3. NEON/AVX2 and cross-platform thread pool;
4. measured INT8/Q4 paths;
5. batched matmat;
6. resident Metal/CUDA subgraphs and overlap.

Do not claim a GPU win from a per-op implementation that copies/synchronizes for
every matvec. The intended GPU unit is prefill, a complete autoregressive step,
or the NanoCodec decoder with resident weights and pooled IO.

## Backend contract

`cpu` is always available. A requested `metal` or `cuda` backend must report one
of: active, not compiled, no device, unsupported model, or runtime failure. For
recoverable cases it falls back to CPU and continues; correctness failures in a
GPU self-test must fail the command, not be hidden as a benchmark result.

Metal is macOS-only and compiled in a separate target. CUDA is Linux/NVIDIA and
compiled in a separate target. The public API must not expose MTL/CUDA handles.

## Testing checklist

Before completion of a change:

1. `make` or the smallest relevant target from a clean build.
2. `make self-test` for touched kernels.
3. Stage parity against the pinned oracle.
4. E2E WAV smoke with explicit language/speaker/seed.
5. Offline vs streaming if the pipeline or codec state changed.
6. `make ubsan`; `make leaks` on macOS when ownership/lifecycle changed.
7. `make asan` in Linux CI for memory-sensitive changes.

If a model, codec or GPU is unavailable, report the exact skipped command and
reason. Never replace a skipped model test with an unrecorded claim.

## Current status

The v1 native path is implemented: the Makefile, CPU SIMD/scalar kernels,
optional Metal/CUDA matmul backends, WAV writer, model-pack verifier, archive
inspector/converter, NeMo oracle helper, and native Magpie
transformer/local-transformer/NanoCodec synthesis exist. GPU builds are
optional and must be validated on the target machine; the current GPU slice
offloads transformer matmuls and kernel-1 FFN matmuls while attention score
loops and the causal codec decoder remain CPU-side.
